# ISMS-ISO-Toolkit Implementation Plan

**Project goal (hobby framing):** Build a practical, code-driven personal toolkit that automates key parts of an ISO 27001 ISMS — risk register + heatmaps, Annex A gap analysis, policy templates, and control mapping — for a fictional small company. Present and maintain the repo strictly as a hobby / learning project.

**Resume intent (not in repo):** Demonstrate hands-on risk management, compliance framework knowledge (ISO 27001:2022), policy writing, and automation skills. The repo itself must never contain "Sec-CV", "portfolio", "CV bullet", job-search references, or numbered project tags. It reads as a clean personal open-source-style hobby repo.

Current state (live): P0–P8 complete. Full end-to-end verification passed. All verification checklists ticked. Project frozen. See todo list and git log.

This plan provides the concrete blueprint, file-by-file, phase-by-phase to reach a complete, impressive, verifiable result.

## Risk Assessment Methodology (to implement)

- Asset-based (aligns with classic ISO 27005 thinking).
- 5×5 qualitative matrix (ubiquitous for small orgs and easy to defend).
- Likelihood (1–5) and Impact (1–5). Impact can be single score or average of CIA — document choice.
- Inherent risk score = Likelihood × Impact.
- Rating bands (example, make explicit):
  - 1–4: Low (green)
  - 5–9: Medium (yellow)
  - 10–15: High (orange)
  - 16–25: Critical (red)
- Treatment: Mitigate (Treat), Accept, Transfer, Avoid.
- Residual risk: either separate L/I after treatment or a reduction factor. Record both.
- Columns in register (inspired by common good templates):
  - ID, Asset, Threat / Vulnerability, Likelihood, Impact, Inherent Score, Rating, Existing Controls, Treatment, Residual Score/Rating, Risk Owner, Review Date, Status, Notes.
- Heatmap: 5×5 count matrix + color + top risks callout.
- Document control tab + version history.
- Clear "Methodology" sheet explaining scales and assumptions.
